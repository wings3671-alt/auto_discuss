# 胡说八道群

让多个 AI(Claude Code、Codex,以及之后想加的其他模型)和你围绕一个议题轮流发言,
把问题讨论深、讨论透。界面像即时通讯软件:左边是讨论列表,中间是对话,右边是白板和成员。

- **只走订阅**:只调用各家命令行工具的订阅登录,绝不走按量计费的 API。
- **平时只动嘴**:AI 只输出文字,讨论记录和白板都由程序执笔。
- **需要时可以派活**:你点名一位成员,它在那一棒可以改文件、跑命令,干完把执行报告交回群里,
  其他成员接着审查。见下面「派活」一节。
- **上下文不膨胀**:AI 每一棒只读"白板 + 最近的发言",不读全文。

## 怎么用

双击桌面的「胡说八道群」。第一次使用、或者把项目文件夹搬了位置之后,先生成一次 App:

```bash
bash macos/build.sh
```

也可以不用 App,在终端里运行 `python3 -m discuss`,再用浏览器打开它打印出来的地址。

## 常用操作

| 想做什么 | 怎么做 |
|---|---|
| 置顶、改名、导出、删除一场讨论 | 在左边列表里右键点它,或打开后点右上角的「⋯」 |
| 找以前聊过的内容 | 左上角搜索框:标题和每一条发言都会搜 |
| AI 说到一半想补充 | 直接在输入框里写,点「插入发言」;它会带着你的话重说这一棒 |
| 让某个 AI 现场干活 | 把输入框下面的「只讨论」改成「派活给某某」,再发送 |
| 给 AI 看一份文件或图片 | 把它拖进窗口(拖到哪儿都行),或点「＋ 文件」,或直接粘贴;它随你下一次发言一起发出 |
| 找回附过的文件 | 点发言里的那枚文件签,访达会打开并选中它 |
| 不想让旁人看到聊过什么 | 点左上角印章旁边的「‹」,整个讨论目录收成一条窄边;再点「›」展开。重启后还是收着的 |
| 把「已收工」那一长串收起来 | 点目录里那一组的标题(置顶 / 进行中 / 已收工 都可以),再点一下展开 |
| 复制某条发言 | 鼠标移到那条发言上,点「复制」 |
| 换名字、头像、主题、字号 | 左下角「设置」。每个人发言笺的颜色就是他头像的底色 |
| 删除时连 NAS 上的备份一起处理 | 删除确认框里勾选;NAS 上那份会挪进「已删除_日期」文件夹,不直接删 |

导出的网页文件存在「下载」文件夹里,样式和图片都嵌在文件里,可以直接发给别人。

## 派活

默认每一回都是纯讨论。想让 AI 动手时,发言前把输入框下面的「只讨论」改成「派活给某某」:

- **只管这一回,只管这一位**。被点名的成员在它那一棒可以改文件、跑命令;其他成员照常只动嘴,
  任务变成审查它干的活。下一回自动回到「只讨论」。
- **危险的事先请示**。删除、覆盖没有备份的文件、批量改名或移动、动 NAS 或云同步文件夹、
  会丢提交的 git 操作、改权限、往外部服务发东西——这些它不会直接做,即使你的吩咐里点名要做:
  它先在发言里说清楚打算做什么、会影响什么,你下一回同意(并再次派活给它),它才动手。
- **讨论记录和白板它改不了**。这两处仍然只由程序执笔,用它的改文件工具去写会被直接拒绝。
- **干完交报告**。它的发言就是执行报告:做了什么、结果如何、还剩什么;发言下面带「派活」标记。
- **出了岔子**。这一棒失败或被你停止后点「重试」,它会先看清现状再接着干,不从头重做。
  用「插入发言」打断正在干活的成员,活会停在半截,它带着你的补充接着干。

Claude Code 和 Codex 类型的成员都能被派活,下拉框里各有一项。两者划权限的方式不同:

- **Claude Code**:哪里的文件都能改;讨论记录和运行数据两个文件夹由程序直接禁止它写。
- **Codex**:在系统沙箱里干活,只能改你主目录里的东西,别处(外置硬盘、NAS)由系统拦住。
  想让它改外置硬盘上的项目,到 设置 → 讨论 → 派活时还能改的文件夹 里加上。
  讨论记录在主目录里,沙箱拦不住,靠派活守则约束。

被派活的那一棒时限更长(设置 → 讨论 → 派活时最长等待)。

## 文件在哪

| 位置 | 内容 | 上传 GitHub |
|---|---|---|
| `discuss/` | 程序本体(Python + 界面) | ✅ |
| `macos/` | App 外壳的源码和生成脚本 | ✅ |
| `tests/` | 自动测试 | ✅ |
| `讨论记录/` | 你的讨论(Markdown)、白板、附件、讨论守则 | ❌ 私人内容 |
| `运行数据/` | 设置、每场讨论的回滚备份、日志、头像 | ❌ |
| `胡说八道群.app` | 生成出来的 App | ❌ |

在 设置 → 备份 里填好 NAS 的挂载点和目标文件夹后,讨论收工时会自动复制过去(只加不删);
NAS 没连上就记为待同步,下次启动或下次收工时补上。

## 程序结构

依赖方向自上而下,上面的模块不认识下面的:

| 模块 | 负责什么 |
|---|---|
| `config.py` | 设置与路径 |
| `document.py` | 讨论文档(Markdown)的读与写,兼容旧终端版的格式 |
| `whiteboard.py` | 状态白板与 STATE_OPS 指令(格式见 `1b_STATE_OPS规格.md`) |
| `prompts.py` | 给 AI 的提示词 |
| `providers.py` | 各家 AI 的调用方式 |
| `engine.py` | 调度:轮到谁、调用谁、写入什么 |
| `server.py` | 本机网页服务,只监听 127.0.0.1 |
| `web/` | 界面(原生 HTML / CSS / JS,无第三方依赖) |

整个程序只用 Python 标准库,不需要安装任何依赖。

## 接入新的模型

- **不写代码**:设置 → 成员 → 添加「命令行工具」,填一条命令。约定是提示词从标准输入进、
  回复从标准输出出。任何有订阅版命令行工具的模型都能这样接入。本地模型选「Ollama」并填模型名。
- **写代码**(需要流式输出、读图、token 统计、能被派活时):在 `providers.py` 里仿照 `Claude`
  加一个类,登记到 `_KINDS`,再把类型名加进 `config.py` 的 `AI_KINDS`。类上的 `assignable`
  说明它能不能被派活;能的话,`run` 要按 `request.hands_on` 决定给不给写权限,并且不许它写
  `request.protected` 里的文件夹。

## 改完代码之后

```bash
python3 -m unittest discover -s tests -t .
```

测试用假的 AI 把各种走法跑一遍,不联网、不碰真实数据、不向 NAS 同步。

## 已知的限制

- Codex 的命令行工具只能整段输出,不能像 Claude 那样逐字显示。
- 每条发言下的"上下文"数字是那一棒里最大一步的真实占用。每一棒都从头读起,所以它不会一轮轮
  累加。Codex 的数字读自它自己保存的会话记录,找不到记录时不显示。
- 本地模型、命令行工具类型的成员只能发言,不能被派活。
- 被派活的成员用不了 MCP,所以操作不了 Lightroom、Final Cut 这类外部软件。
- 附件单个最大 50 MB,会复制一份存进这场讨论的附件夹(所以原文件之后改了,AI 看到的还是当时那份)。
  PNG / JPG 当图片显示;其余当文件,AI 用读文件工具打开——文本、代码、PDF 它读得懂,
  视频、压缩包这类它打不开。
- AI 每一棒都拿得到你附过的所有文件的路径;图片只看你最近一次发言附的。
- AI 给的图片链接只显示为链接,不在界面里显示图片。
- 「命令行工具」和「Ollama」类型的成员看不到附图,也打不开附件。
- 「插入发言」会丢掉 AI 已经说了一半的话,它带着你的补充从头重说这一棒。
- 退出 App 会中断正在进行的那一棒(已说完的不受影响,下次打开可点"重试")。
